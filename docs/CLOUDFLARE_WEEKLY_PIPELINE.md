# Cloudflare 주간 논문 알림 구현 현황

## 확정한 범위

사용자가 2026-09-13 승인한 순서: 주간 HF 상위 3편 → 요약 안정화 → Discord
테스트 발행 → 예약 실행과 복구 → 학기별 기초 콘텐츠. Workers Free는 사용자가 확인했다.
Free 계정 확인과 실제 CPU 여유 검증은 별개다. 기존 GAS/Python 설명은 과거 기록이다.

## 이번 구현

- `POST /weeks/2026-W37`: HF `/api/daily_papers?week=2026-W37&limit=3` 조회.
  인증 필요. 유료 API는 호출하지 않는다. 정렬 옵션을 붙이지 않으며 반환 순서를 보존한다.
- 3건이 모두 유효하고 중복 ID가 없을 때 `weekly_editions`에 첫 스냅샷을 저장한다.
  week PK / snapshot_json / created_at. 스냅샷에는 조회 시각, 순위, 추천 수, 제목,
  출처 URL, 모델과 논문별 작업 ID를 저장한다. 동시 호출도 하나의 스냅샷을 공유한다.
- `POST /weeks/2026-W37/generate`: LIVE_ENABLED=true일 때 저장된 세 논문을 각각
  독립 Workflow로 시작한다. 한 편의 시작 실패도 다른 두 편을 막지 않는다.
  기존 작업은 다시 시작하지 않는다. dispatch_unknown은 수동 확인 대상이다.
- `GET /weeks/2026-W37`: 순위별 작업 상태 조회.
- 같은 논문·모델·코드 리비전은 다른 주차에도 같은 작업 ID를 사용해 요약을 재사용한다.
  이미 저장된 주차의 작업 ID는 코드 업데이트로 변경되지 않는다.
- 원문 인용은 모델이 선택한 문장 ID를 코드가 원문 문장으로 치환한다. 실제 의미의
  뒷받침 여부까지 자동으로 보장하지 않으며 결과는 검토 대상이다.
- 본문 발췌는 절별로 분산한다. 1.5MB를 넘거나 HTML이 없으면 HF 원문 초록이
  있을 때만 abstract로 전환하며, 실패 이유와 분석 범위를 저장한다.
- HF 페이지 dateString을 2021-W01(2020-12-27), 2025-W01(2024-12-29),
  2026-W37(2026-09-06)에서 확인했다. 일요일 시작·1월 1일 포함 주를 1주차로 계산한다.
  예약은 UTC 기준 직전 완료된 일~토 주차를 선택한다. 사용자 지정 시간은 월요일
  오전 9시 KST(월요일 00:00 UTC)다. 트리거는 CPU 검증 전까지 등록하지 않는다.
- `WeeklyPipeline`은 주간 목록 확정 → 논문별 작업 시작 → 10초 간격으로 최대 10분
  상태 확인 → 단일 주간 메시지 발행을 수행한다. 잠자는 시간에는 단계 계산을 수행하지 않는다.
- `GET /weeks/:week/preview`로 실제 발행 payload를 조회한다. `POST /weeks/:week/publish`는
  DELIVERY_ENABLED=true와 Webhook Secret이 필요하며, LIVE_ENABLED와 독립적으로 제어한다.
- `weekly_deliveries`: week PK, in_flight/sent/unknown, 실제 payload, 메시지·채널 ID,
  오류 코드, 생성 시각. 먼저 예약한 한 요청만 보낸다. 응답이나 저장이 불명확하면
  unknown으로 남기고 자동 재전송하지 않는다. unknown/in_flight는 관리자가 실제 채널을
  확인해야 하며 현재 자동 해제 명령은 없다.
- `weekly_runs`: week PK, queued/running/complete/blocked/dispatch_unknown, 오류·시각.
  예약 실행 중복을 차단한다. 생성 실패는 무조건 재생성하지 않는다.
- `POST /diagnostics/sources/:paper_id`는 인증된 소스 수집 전용 진단이다. 모델 호출,
  Discord 발행, DB 쓰기를 하지 않는다.

## 실행

```bash
npm run cf:typecheck
npm run cf:test
node cloudflare/scripts/check-persistence.mjs
npx wrangler d1 migrations apply discord-study-probe --remote --config cloudflare/wrangler.jsonc
npx wrangler deploy --config cloudflare/wrangler.jsonc
node cloudflare/scripts/weekly.mjs --week 2026-W37
node cloudflare/scripts/weekly.mjs --week 2026-W37 --generate
node cloudflare/scripts/weekly.mjs --week 2026-W37 --status
node cloudflare/scripts/weekly.mjs --week 2026-W37 --preview
node cloudflare/scripts/secrets.mjs --discord
node cloudflare/scripts/weekly.mjs --week 2026-W37 --publish
node cloudflare/scripts/observe.mjs 2608.12564
```

`--generate`만 유료 호출을 시작한다. 로컬 관리 토큰은 기존 승인된 ignored 파일에서
읽으며 출력하지 않는다. 결과는 `artifacts/cloudflare/weekly-<week>.json`에 저장한다.
검증 종료 시 LIVE_ENABLED=false를 배포하고 조회만 유지한다.

## 남은 단계

1. 원격 CPU 여유 확인과 운영 안정화. 상위 3편 기능 검증은 완료했다.
2. 초보자용 사전 개념과 기존 방법과의 차이를 포함한 최종 소개 형식 정교화.
3. Discord 테스트 채널 발행·중복 방지 검증은 완료. 불명확한 전송의 확인·복구 도구 보완.
4. 주차 경계 검증, 예약 실행·누락 탐지·운영 복구.
5. 학기별 검토된 기초 학습 콘텐츠와 로테이션 설정.

사용자가 기존 .env Webhook이 테스트 채널임을 확인한 뒤 Secret을 등록하고 발행했다.

CPU 측정 단위를 GraphQL introspection으로 확인했다: Workers quantiles는 마이크로초,
Workflows cpuTime은 밀리초다. 1위 논문 작업의 누적 CPU는 346ms였고, 원시 이벤트도
작업별 누적값 형태라 사용자 단계별 비용을 바로 분리할 수 없었다. 실제 전송 HTTP는
wrangler tail에서 CPU 11ms, wall 2,083ms, outcome ok로 관측했다.
무료 한도 여유를 보장할 수 없어 자동 운영을 아직 활성화하지 않았다.

검증 후 LIVE_ENABLED, DELIVERY_ENABLED, SCHEDULE_ENABLED는 모두 false로 복원한다.
현재 자동 기초 학습 콘텐츠는 아직 구현하지 않았다. 주간 알림 운영 안정화 후 진행한다.

## CPU 최적화 진행 기록

동일한 2608.12564를 모델 호출 없이 진단했다. 소스 처리 CPU가 초기 275ms,
MathML 제외 후 65ms, 필요한 문단 조각만 먼저 고른 뒤 29ms로 줄었다.
현재 파서는 MathML을 선형 탐색으로 제외하고 문단 내부 태그를 제거한 다음
`entities.decodeHTML`로 엔티티를 해석한다. 전체 HTML은 1.5MB 상한,
엔티티 해석에 제공하는 조각은 36,000자 상한이다.
수식은 `[formula omitted]`로 표시하며 해당 표시가 있는 문장은 인용 후보에서 제외한다.
이는 수식 전개를 분석하는 전체 논문 독해 기능이 아니다.

기존 W37 결과는 probe-v3에서 생성·검증·발행됐으며 이후 최적화로 재생성하지 않았다.
파이프라인 리비전이 달라진 미시작 작업은 edition_revision_changed로 차단한다.
이미 완료된 작업과 주간 순위는 계속 유지된다.

단위·통합 테스트와 타입 검사를 실행한다. 무료 CPU 검증이 완료되기 전에는
월요일 오전 9시 예약 트리거를 등록하지 않는다. 해당 시각은 사용자와 확정한 설정이다.

2026-09-13 단계별 HTTP 진단에서 메타데이터 3ms, 본문 다운로드 15ms,
전체 수집·파싱 24ms를 관측했다. `Accept-Encoding: identity`를 적용한 비교에서는
각각 2ms, 11ms, 25ms였다. 단일 관측이므로 압축 해제가 병목이라고 단정하지 않는다.
모두 outcome=ok였지만 [Free 단계당 10ms 제한](https://developers.cloudflare.com/workflows/reference/limits/)
이내 운영을 입증한 결과는 아니다. 다음 검증은 다운로드와 파싱을 별도 Workflow
단계로 나누고 실제 단계별 CPU를 확인하는 것이다. 기존 요약과 Discord 메시지는 유지한다.

예약 시각은 월요일 09:00 Asia/Seoul(UTC 월요일 00:00)이며, 활성화 시 Cron 표현식은
`0 0 * * MON`이다. 현재는 Cron 등록이 없고 세 실행 게이트도 모두 false다.

## 임베드 개편 v2

- 메시지는 content 없이 임베드 3개만 사용한다. 별도 안내 footer도 제거한다.
- 제목: `9월 2주차 AI 뉴스: 1위 · 기존 논문 제목`. 1~3위 순서를 유지한다.
- 월·주차는 HF 집계 마지막 토요일의 UTC 월과 날짜 기준이다. 1~7일은 1주차,
  8~14일은 2주차다. 2026-W37은 9월 2주차이며 발송일 기준이 아니다.
- 세로형 fields 순서: 한줄 소개, 핵심 아이디어, 기존 방법과의 차이,
  입문자 사전 개념, 한계, 출처. 출처는 arXiv/HF 링크와 본문 발췌·초록 범위를 포함한다.
- 신규 생성은 schema_version=2이며 differences는 근거가 있는 비교 0~2개,
  prerequisites는 용어·뜻풀이 2~3개다. 비교도 claims와 동일한 원문 인용 검증을 거친다.
  비교 근거가 없으면 빈 배열을 반환하고 출력에서 확인 불가로 표시한다.
- schema_version 없는 기존 결과는 계속 읽되 새 항목을 임의로 만들지 않는다.
  기존 결과에 비교/사전 개념이 없다는 안내를 표시한다. 새 API 응답에는 v2를 강제한다.
- D1 테이블 변경 없이 result_json을 확장한다. 파이프라인 리비전 probe-v9로 구분한다.
- 제목 256자 및 모든 임베드 합계 6,000자 제한을 검증한다. 긴 제목은 원문을 유지하되
  Discord 제한에 걸리는 경우 말줄임한다. 전문은 제목의 논문 링크에서 확인한다.
- 이미 발송한 W37 메시지는 자동 수정·재발송하지 않는다. 새 렌더러는 preview 및
  이후 새 주차 발행에 적용된다. 예약 게이트는 CPU 검증이 끝날 때까지 비활성이다.

- 호출·발송 기록: ignored `artifacts/cloudflare/preview-v2-W37/`.
- 기존 W37 발송 기록과 메시지는 유지했다. 이번 실행은 로컬에서 운영 요약·렌더러

## 설명형 임베드 v3

사용자 요청으로 출처에서 본문 발췌/초록 기반 표시를 제거했다. coverage 메타데이터는
내부 기록 및 생성 입력에서 유지한다. 수집 방식은 바뀌지 않았으며 전체 본문/PDF를
새로 읽었다는 의미가 아니다.

- 제목은 `9월 2주차 AI 뉴스: 1위 · 기존 제목`을 유지한다.
- 세 줄 요약(220자), 연구 배경(230자), 해결 과정(최대 3개 단락, 각 125자),
  결과(최대 2개, 각 95자), 사전 개념(2~3개), 연구 한계(150자), 출처 순서다.
- 연구 배경과 작동 과정을 연결해 설명한다. 신규 생성의 출력 상한은 2,600토큰이다.
- 연구 한계에는 연구 자체의 명시된 한계만 적는다. 자료 부족에 대한 설명은 넣지
  않으며 명시된 한계가 없으면 빈 문자열을 저장하고 필드를 생략한다. 결과도 근거가
  없으면 빈 배열을 저장하고 생략한다. 출처 필드는 arXiv/HF 링크만 포함한다.
- schema_version=3, background/results 추가, claims가 방법 설명을 담당한다.
  결과도 기존 주장과 같은 인용 검증을 적용한다. v1/v2 저장 결과는 계속 읽는다.
- 신규 실행 revision=probe-v10. 원격 예약 및 발송 게이트는 비활성 상태를 유지한다.
- 이번 명시적 추가 테스트는 `artifacts/cloudflare/preview-v3-W37`에 최대 3회 호출과
  단일 발송 기록을 남긴다. v2 테스트 기록과 기존 Discord 메시지는 보존한다.

### v3 실제 검증 및 교정

3편을 생성·발송한 후 영어 출력과 미완결 문장을 발견했다. 생성 결과의 인용문 존재
검증만으로 출력 품질이 보장되지 않았으므로 한국어 비율·문장 종결·세 줄 요약 형식
검사를 추가했다. 원본 API 결과는 그대로 보존하고 원문과 대조한 한국어 교정 결과를
별도 `.reviewed.json`으로 저장했다. 같은 메시지를 PATCH하여 중복 게시하지 않았다.
- 메시지: 1548628566810435632, 채널: 1486941167823097937.
- 최종 필드 본문 분량: 981 / 996 / 953자. 자료 범위 표시는 없다.
- API 3회 입력 10,623 / 출력 1,270토큰. 교정에는 추가 API 호출 없음.
- 이 결과는 생성 후 편집 검토를 거쳤으며 무검수 자동 생성의 품질 통과를 의미하지 않는다.

### 전문 용어·이모지 표시 규칙
